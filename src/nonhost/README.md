# Non-zebrafish reads from  datasets in SRA

## Features
- Input a list of SRA run accessions
- Output non-zebrafish reads as compressed fastq files
- QC reads and use three aligners to map/remove zebrafish reads
- Distributed computing on HPC environments (Slurm job scheduler)
- Highly automated


## Usage

### Clone the repository
```
git clone https://github.com/czbiohub-sf/Zebrafish-RNAquarium
```
### Install dependencies
The non-zebrafish reads pipeline requires the following dependencies in `PATH`:
 - hisat2 ( https://daehwankimlab.github.io/hisat2/download/ )
 - bowtie2=2.4.5 ( https://sourceforge.net/projects/bowtie-bio/files/bowtie2/ )
 - czid-dedup=0.1.0 ( https://github.com/chanzuckerberg/czid-dedup )
 - fastp=0.23.2 ( https://github.com/OpenGene/fastp )
 - FastQC=0.12.1 ( https://www.bioinformatics.babraham.ac.uk/projects/fastqc/ )
 - gmap-gsnap=2021-12-17 ( http://research-pub.gene.com/gmap/ )
 - HTSeq=2.0.2 ( https://htseq.readthedocs.io/en/master/install.html )
 - Price=1.2 ( https://derisilab.ucsf.edu/software/price/index.html )
 - samtools=1.16.1 ( https://www.htslib.org/download/ )
 - sratoolkit=3.0.0 ( https://github.com/ncbi/sra-tools/wiki/02.-Installing-SRA-Toolkit )
 - STAR=2.7.10 ( https://github.com/alexdobin/STAR )

Alternatively, most pre-installation can be skipped by running the nextflow
pipeline with the `-profile conda`, `-profile mamba`, `-profile docker`, or `-profile singularity` parameters,
which will automatically pull and use containers or environments for most steps. (The 
conda/mamba option is preferred)

**in this case, currently `fastq-lengths`, `PRICE`, and `czid-dedup` are not
available as containers**.  `gmap` is also installed from source due to its containers having issues.
`nextflow run install-deps.nf` or `setup-minimal.sh` will download these.
e.g.:
```
./setup-minimal.sh
nextflow run -with-singularity
```


### Create a working directory and input list
```
cd Zebrafish-RNAquarium/src/nonhost
mkdir test && cp data/SRA_accession_list.test.txt SRA_accession_list.test.txt
```

### Generating reference indexes
The nonhost pipeline needs reference genome information for STAR mapping.
There are two ways of providing this.

1. pre-generated index directories (i.e. previously generated by STAR)
provide the following parameters:
 - `--hisat-ref-indexes <hisat2 reference index path>`
 - `--star-ref-indexes-ercc <star reference genome index path>`
 - `--star-ref-indexes <star reference genome index without ERCC path>`
 - `--bowtie-ref-indexes <bowtie2 reference index path>`
 - `--gmap-ref-indexes <gmap/gsnap reference index path>`
 - `--ref-genome-gtf <reference.gtf>`

2. reference genome assembly and spike-in sequences (the required indexes will be generated for you)
provide the following command line parameters:
 - `--ref-genome <primary_assembly.fa.gz>`
 - `--ref-genome-gtf <reference.gtf>`
 - `--ercc <ERCC.fa>`
 - `--ercc-gtf <ERCC.gtf>`

the host reference genome, and *only* the host reference, must be `bgzip` compressed and indexed
with `samtools faidx`.

for example, for ensembl release 108 of the *Danio rerio* genome:
```
--ref-genome Danio_rerio.GRCz11.dna_sm.primary_assembly.fa.gz
--ref-genome-gtf Danio_rerio.GRCz11.108.gtf
--ercc ERCC92.fa
--ercc-gtf ERCC92.gtf
```


### Running the main pipeline
```
PATH=$PATH:$PWD/bin nextflow run main.nf --ref-genome Danio_rerio.GRCz11.dna_sm.primary_assembly.fa.gz \
--ref-genome-gtf Danio_rerio.GRCz11.108.gtf \
--ercc ERCC92.fa --ercc-gtf ERCC92.gtf \
--accession-list SRA_accession_list.test.txt
```
